BuildCipher 实验执行与沙盒验证架构图

适合作为论文或答辩里的“主图 3”。这一版聚焦实验环境：知识输入如何进入、攻击如何在沙盒内执行、证据如何被记录、修补如何回归验证，特别适合讲“实验架构”而不是泛泛讲系统架构。

实验输入

业务需求 场景、目标、约束、交付形式
知识资料 知识库、论文、规则、企业文档
项目历史记忆 上一轮漏洞、补丁、剩余风险和反思摘要
生成/审计 Agent 在实验开始前形成待测方案和初步风险判断

核心实验区：受控沙盒

这里是整套系统最像“实验平台”的部分。它不是直接打真实生产服务器，而是在可控环境中部署、攻击、记录、评估和修补。

阶段 A：部署与准备

目标服务部署 将候选算法部署成可攻击的模拟服务
沙盒调度器 控制预算、权限、执行边界
上下文压缩 给不同 Agent 分发独立输入窗口
↓

阶段 B：攻击与观测

攻击 Agent 动态决定试探策略、继续或切换路径
模拟服务器 承接请求并暴露流量变化与异常行为
遥测采集 记录流量、日志、指标和攻击工件
↓

阶段 C：漏洞判定与修补

评估 Agent 给出漏洞定级与处置优先级
修补 Agent 生成补丁、修复建议和回归检查
回归验证 再次部署并检查漏洞是否消失
↓

阶段 D：回放与优化

时间线回放 回看整个实验链路发生了什么
项目级记忆 沉淀攻击经验、补丁经验与残余风险
最终交付 输出中文报告、伪代码和代码实现

实验输出

漏洞证据 攻击日志、发现结果、流量指标、工件引用
修补方案 补丁描述、验证步骤、回滚说明
回放记录 timeline、snapshot、结构化交接和证据索引
企业交付物 中文报告、伪代码、Python/C++ 代码

最适合的用途

这版特别适合实验章节、系统实现章节、或者答辩里解释“沙盒到底在系统里扮演什么角色”。

怎么口头解释

可以直接说：我们不是只做方案生成，而是在受控实验环境里完成部署、攻击、判定、修补和回归验证。

当前边界

这张图表达的是实验执行框架和目标状态；真实容器执行平面、远程执行器和完整回执服务仍在后续主线中。
