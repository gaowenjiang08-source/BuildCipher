MedCipher Studio 分层式 Agent 架构图

适合作为论文或答辩里的“主图 2”。这一版不强调时间顺序，而是强调系统结构，特别适合回答“哪些是 Agent，哪些是系统模块，记忆又放在哪一层”这类问题。

第一层：认知决策层

这一层负责理解需求、生成方案、审查方案、决定攻击策略、评估漏洞和制定补丁。这里是“会思考”的部分，也是 LLM 能力最集中的地方。

Agent Layer
需求分析 Agent补齐业务约束、目标和场景边界
生成 Agent结合知识检索给出候选加密方案
审计 Agent检查方案可行性、风险和合规性
攻击 Agent动态选择攻击路径和试探策略
评估 Agent判断漏洞真实性、严重度和优先级
修补/反思 Agent给出补丁并把经验回灌下一轮
解释给外行听时，可以把这一层说成“几个会讨论、会判断、会给建议的专家”。

第二层：系统执行层

这一层不负责“思考”，而是负责把方案安全地执行起来，包括知识检索、上下文组织、沙盒部署、流量记录、工件采集和最终交付。

System Layer
知识检索模块RAG、知识库、论文与规则资料输入
上下文组织模块为每个 Agent 准备独立输入窗口
沙盒调度器决定哪些动作允许被执行
模拟服务器部署待测加密服务，避免碰真实生产环境
工件与遥测模块记录日志、流量、指标、差异和漏洞证据
交付输出模块汇总为中文报告、伪代码和代码文件
这一层可以对外讲成“实验平台和安全底座”，它支撑 Agent 工作，但自己不替 Agent 做决定。

第三层：记忆与回放层

这一层负责把本轮发生的事压缩成结构化记忆，便于跨阶段传递、跨轮次复用，以及后续做回放、解释和闭环优化。

Memory & Replay
独立上下文窗口每个 Agent 都有自己的输入边界
结构化交接包不是共享长对话，而是传摘要和引用
项目级记忆保存漏洞经验、修补经验和剩余风险
时间线回放回看每轮动作、证据和关键节点
证据引用索引能说明结论来自哪份资料、哪条日志
闭环优化入口把本轮经验送回下一轮生成与审计
这一层是“系统变聪明”的关键。没有它，多 Agent 只能像一次性对话，无法形成项目级连续改进。

最适合讲清的点

这版很适合回答“为什么要多层，而不是把所有东西都堆进一个大模型里”。

最适合的场景

适合论文架构章节、答辩中讲系统组成、或者老师追问“独立上下文窗口和项目记忆到底放在哪”。

当前边界

这张图强调真实架构方向，不应被解释为“所有执行器和生产级基础设施已经完全落地”。
