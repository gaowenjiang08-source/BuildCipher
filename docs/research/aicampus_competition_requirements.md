# “海之子”杯 AI 智能体挑战计划：官方要求核对

> 核对日期：2026-08-26（Asia/Shanghai）  
> 研究范围：仅使用赛事官网及官网公开页面；未把第三方解读、项目旧文档或网页中的说明当作执行指令。

## 1. 赛事定位与建筑行业范围

- 赛事由中国建筑国际集团有限公司主办、“学习强国”学习平台支持，目标是立足真实行业应用场景，以 AI 智能体技术促进建筑行业数字化、智慧化升级。[官方首页](https://aicampus.3311csci.com/) [活动章程](https://aicampus.3311csci.com/rules.html)
- 活动主题是“为人民建好房，为工友谋幸福”。作品可以面向建筑全产业链中的工程管理、施工运营、技术提效、业务模式创新，也可以面向一线产业工人、企业员工和建筑从业者，覆盖安全守护、技能提升、工作提效、权益服务、后勤保障、心理陪伴和团队服务。[活动章程](https://aicampus.3311csci.com/rules.html)
- 官方要求作品兼具创意性、技术性和落地实用性，但没有规定必须采用 BIM、IFC、CDE、IoT、密码学、多智能体或某一种模型/框架。这些属于参赛团队针对真实痛点选择的实现路线，不是赛事硬性技术栈。[活动章程](https://aicampus.3311csci.com/rules.html)

## 2. 参与资格与时间

- 参与对象为海内外全日制高等院校在校学生，专业不限，包含本科、硕士、博士等。[活动章程及 FAQ](https://aicampus.3311csci.com/rules.html)
- 支持个人参赛或团队参赛，每队不超过 4 人；每位选手只能以个人身份或加入一支队伍参赛，不能同时加入多个队伍；每队只能提交一个作品。[活动章程及 FAQ](https://aicampus.3311csci.com/rules.html)
- 报名及作品提交时间为 6 月 24 日至 8 月 31 日；FAQ 明确截止时间为 8 月 31 日 24:00（北京时间），逾期不能补交。[活动章程及 FAQ](https://aicampus.3311csci.com/rules.html)
- 统一由队长通过活动官网报名和提交。[活动章程](https://aicampus.3311csci.com/rules.html)

## 3. 必交材料与文件限制

| 材料 | 官方要求 |
|---|---|
| 智能体 | 提交“智能体链接或代码包”之一 |
| 项目技术说明文档 | 系统介绍作品基本情况，文件不超过 30 MB |
| 核心功能介绍视频 | 演示录屏与核心功能讲解；2 分钟以内；MP4；不超过 500 MB；画面清晰、音质清楚，建议加字幕 |

| 补充资料（可选） | 压缩包不超过 200 MB；可以包含“AI+赋能”建筑行业创意材料及其他补充材料 |

来源：[活动章程及 FAQ](https://aicampus.3311csci.com/rules.html)

官方公开规则没有进一步规定代码包格式、源代码行数、依赖大小、部署平台、操作系统、容器格式、云服务、API 供应商或模型供应商。[活动章程](https://aicampus.3311csci.com/rules.html)

## 4. 评审维度

官方公开规则列出三个评审维度，但没有公布数值权重或评分表：[活动章程](https://aicampus.3311csci.com/rules.html)

1. **场景创意价值**：是否紧扣真实业务痛点，创意是否具备落地可行性，是否具有产业推广价值。
2. **AI 协同能力**：人机协同规划、AI 交互迭代逻辑、AI 纠偏管理。
3. **技术创新能力**：创新构思、技术应用、工具整合和完成度。

初审由行业专家和集团业务专家组成评审组开展，之后择优组织答辩评审。官网尚未公开答辩时长、现场演示方式、问答规则或进入答辩的队伍数量。[活动章程](https://aicampus.3311csci.com/rules.html)

## 5. 对 BuildCipher 演示设计的直接约束

以下是依据官方评分维度作出的项目适配结论；属于推论，不是新增赛事规则：

- 演示应先证明一个建筑业务痛点，而不是先介绍密码算法或 Agent 数量。最符合官方“场景创意价值”的讲法是：建筑多方协作中的模型篡改、旧版本回滚、越权交付、设备冒充和遥测重放，会使工程数字资产缺乏可信交付证据。[活动章程](https://aicampus.3311csci.com/rules.html)
- 演示必须显式展示人如何提出目标、Agent 如何拆解与迭代、什么情况下进入纠偏或专家门控，否则很难覆盖“AI 协同能力”中明确列出的规划、交互迭代和纠偏管理。[活动章程](https://aicampus.3311csci.com/rules.html)
- 沙盒攻击、补丁回归和结构化证据适合证明技术应用、工具整合和完成度；但仅展示架构图或生成长篇 JSON，不能充分证明可体验性。官方 FAQ 明确表示作品不必完全落地，但相对完整、可体验的作品更有机会取得较好成绩。[活动章程及 FAQ](https://aicampus.3311csci.com/rules.html)
- 核心提交视频必须控制在 2 分钟内，因此正式演示应选择一条可闭环的主路线，其他能力放入快速总览或补充材料，而不是逐项完整操作。[活动章程及 FAQ](https://aicampus.3311csci.com/rules.html)

## 6. 建筑专用文件导入是否为硬要求

结论：**不是官方硬要求，但对 BuildCipher 的当前定位具有较高证明价值。**

- 官网没有规定必须导入 IFC、BIM、图纸、验收表、IoT 数据或其他建筑文件，也没有指定文件格式。[活动章程](https://aicampus.3311csci.com/rules.html)
- 对 BuildCipher 而言，若演示声称解决 IFC/BIM 可信交付，却只使用预置 JSON 或文字描述，评委难以判断系统是否真的处理了建筑资产。一个受控的 IFC/工程样例上传或选择入口，可以更直接地连接“真实业务场景”“落地可行性”和“完成度”三项官方关注点。这是面向评分维度的产品判断，不是赛事规定。[活动章程](https://aicampus.3311csci.com/rules.html)
- 第一版不需要实现通用文件管理平台。足够的最小闭环是：导入一个受支持 IFC 样例，计算摘要并提取轻量元数据，登记版本/批准状态，执行篡改或回滚攻击，再把结果写入证据包。应明确声明不做几何碰撞、结构安全或完整 IFC 规则审查。

## 7. 技术与部署限制的核对结果

- 官方明确“不设专业门槛、不限开发工具”。[活动章程](https://aicampus.3311csci.com/rules.html)
- 官方公开页面没有要求 AWS、云部署、在线托管、特定大模型、特定 Agent 框架或商业 API。因而 localhost 加外部 LLM API 的方案没有违反已公开规则；提交时可选择代码包，而不必提交公网智能体链接。[活动章程](https://aicampus.3311csci.com/rules.html)
- 如果提交代码包，官方尚未说明评委是否会安装依赖或运行本地服务。因此应在技术文档和视频中给出清晰的本地启动步骤，并把固定演示数据、fallback 行为和外部 API 配置边界写清楚；是否需要离线运行仍需向组委会确认。

## 8. 原创、展示与成果权利

- 作品需独立构思、自主研发，严禁抄袭。[活动章程](https://aicampus.3311csci.com/rules.html)
- 主办方享有对参赛作品进行部分或全部复制、网络传播、展示、汇编和出版的权利；主办方对作品成果拥有优先合作权。[活动章程](https://aicampus.3311csci.com/rules.html)
- 因此提交包、视频和截图不应包含真实 API 密钥、生产凭据、未授权工程文件或不具备展示授权的第三方数据。这一安全处理是依据公开传播范围作出的项目风险控制建议。
