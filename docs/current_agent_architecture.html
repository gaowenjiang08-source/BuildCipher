MedCipher Studio / 面向演示与答辩

一张给外行人看的
多智能体架构图

这套系统做的事情很简单：先生成加密方案，再自己审查，再在沙盒里模拟攻击， 发现问题后给出修补方案，最后形成中文交付，并把经验留给下一轮继续变聪明。

中文交付优先 真实 LLM 决策 沙盒验证闭环 每个 Agent 独立上下文

先看一条主流程

如果把整个系统讲给不懂技术的人听，可以直接讲下面这 7 步。它描述的是“一个需求如何变成可验证、可修补、可交付的方案”。

1

提出需求

用户输入业务目标，例如“我要一个更安全的加密服务”。

  • 明确场景
  • 补齐约束
  • 准备资料
2

生成方案

生成 Agent 结合知识库和技能提示词，给出候选设计与伪代码。

  • 方案草案
  • 实现思路
  • 风险假设
3

内部审计

审计 Agent 先挑毛病，避免一开始就把不靠谱的方案推下去执行。

  • 查漏洞点
  • 查合规性
  • 给整改意见
4

沙盒部署

系统在受控沙盒里搭一个“模拟服务器”，把待测算法真正跑起来。

  • 不碰真实生产环境
  • 可记录流量
  • 可留痕回放
5

模拟攻击

攻击 Agent 根据当前结果继续试探，寻找弱点，而不是机械跑固定脚本。

  • 动态换策略
  • 看结果再决定
  • 输出攻击证据
6

评估与修补

评估 Agent 判断漏洞值不值得修，修补 Agent 给出补丁与回归验证方案。

  • 漏洞定级
  • 生成补丁
  • 再次验证
7

形成交付

输出中文报告、伪代码、Python/C++ 代码，并把经验沉淀给下一轮。

  • 可读报告
  • 证据引用
  • 闭环优化
闭环重点：最后一步不会结束在“报告写完”，而是把这轮经验回灌给下一次生成与审计。

背后其实分成三层

外行最容易把“所有模块都当成 Agent”。更清楚的讲法是：上层是会思考的 Agent，中层是负责安全执行的系统底座，下层是记忆与回放。

第一层：会做判断的 Agent

这层负责“思考、判断、给方案”。真正有 LLM 决策能力的主要都在这里。

认知层
生成 Agent 根据知识库提出方案
审计 Agent 先找方案中的问题
攻击 Agent 决定怎样攻击更有效
评估 Agent 判断漏洞严重程度
修补 Agent 提出补丁与回归验证
反思 Agent 把经验留给下一轮

第二层：负责安全执行的系统底座

这层不负责“想”，而是负责“让事情在安全、可控、可追踪的环境中发生”。

执行层
知识检索 给 Agent 提供资料和证据
上下文编排 控制每个 Agent 该看什么
沙盒调度器 决定是否允许执行
模拟服务器 部署待测加密服务
流量与工件记录 保存日志、指标、漏洞证据
交付输出器 汇总为报告和代码

第三层：项目记忆与回放

这层负责“记住这次发生了什么”，让系统不是一次性对话，而是能持续进步的项目型系统。

记忆层
独立上下文窗口 每个 Agent 只看自己的摘要
结构化交接 不是共享一大段长对话
项目级记忆 记录本次经验与风险
时间线回放 回看每一步做了什么
证据引用 能解释结论从哪里来
下轮优化 把经验喂给下一次生成

为什么这个架构更容易讲清楚

这部分适合答辩时直接口头解释，用来避免听众产生误解。

不是所有模块都是 Agent

Agent 负责思考和决策，系统模块负责检索、调度、落盘、回放和可视化。这样分开后，职责就很清楚。

不是共享一个超长上下文

每个 Agent 都有自己的独立上下文窗口，阶段之间靠结构化摘要传递信息，这样更省上下文，也更可维护。

不是只会生成报告

系统会真正经历“方案生成 → 模拟攻击 → 评估修补 → 回归验证”，最后再形成交付，所以它是闭环系统，不是单次写作工具。

对外展示时建议这样解释颜色

如果你要截图放 PPT，这一块可以直接当图例。

橙色 = Agent

会思考、会决策

这些模块带有真实 LLM 能力，负责提出方案、决定攻击策略、评估漏洞和修补问题。

绿色 = 系统底座

会执行、会控制

这些模块负责知识检索、沙盒调度、模拟服务器、日志记录和交付输出，不负责“思考”。

蓝灰 = 记忆与回放

会记住、可回看

这些模块负责上下文摘要、项目记忆、证据引用和时间线回放，是闭环优化的关键。

一句话总结： MedCipher Studio 不是“几个 Agent 轮流聊天”，而是一套把生成、审计、攻击、评估、修补、回放和交付串起来的多智能体闭环系统。 当前重点仍然是沙盒内的可控验证与项目级记忆，不把未完成的生产级执行器说成已经落地。
