BuildCipher 多智能体闭环主流程图

适合作为论文或答辩里的“主图 1”。重点讲系统从需求输入到中文交付的完整闭环，让外行一眼看懂每一步是谁在做事、为什么要做这一步。

橙色：Agent 决策 绿色：系统执行 蓝灰：记忆与回放 金色：交付输出
业务需求输入 用户提出场景、约束、目标和交付要求
→
生成 Agent 结合知识库、Skill 提示词和历史经验生成候选方案
→
审计 Agent 先从理论、实现和合规角度审查方案质量
沙盒部署模块 将候选算法部署成受控的模拟服务器实例
→
攻击 Agent 基于实时结果决定攻击路径，而不是只跑固定脚本
→
流量与工件采集 记录日志、指标、漏洞证据、攻击轨迹和差异结果
评估 Agent 判断漏洞是否成立、严重度如何、修补优先级多高
→
修补 Agent 给出补丁、验证步骤和回归检查方案
→
回归验证模块 再次部署并复测，检查问题是否真正被修掉
项目级记忆 保留阶段摘要、结构化交接、漏洞经验和上下文压缩结果
→
时间线回放 支持回看“谁做了什么、为什么这么做、证据来自哪里”
→
中文交付输出 输出报告、伪代码、Python/C++ 代码与证据引用
闭环优化：本轮攻击与修补经验会回流到下一轮生成与审计，系统会越跑越懂这个项目。

图的重点

这版最适合第一页。它强调“不是一次性生成报告”，而是一个从设计到验证再到修补的闭环。

适合怎么讲

可以用一句话解释：系统会先提出方案，再自己找问题，再在沙盒里验证，最后给出带证据的交付结果。

当前边界

这张图展示的是架构方向与已落地主线，不等于已经完成生产级容器执行器或远程攻击平面。
